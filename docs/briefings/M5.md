## 2. How it works

- **TWR.** End-of-day valuations at flow boundaries: flow-day subperiods `(V_t − V_(t−1) − CF)/(V_(t−1)+CF)`, gap subperiods ratio. External flows are contributions/withdrawals (+/−) and the SIP contribution leg once; internal moves never flow.
- **Modified Dietz.** `(V_E − V_S − ΣCF)/(V_S + Σ w_iCF_i)`, `w_i=(T−t_i)/T`, `T` inclusive calendar days.
- **XIRR.** Investor-perspective flows (inflows negative, terminal positive), actual/365, domain `(−0.999999, 1000)`, 2,001-point `ln(1+r)` scan with bisection refinement and Newton-from-midpoint fallback; statuses `SUCCESS / MULTIPLE_ROOTS / NO_ROOT_IN_DOMAIN / NO_ROOT_PROVEN / NON_CONVERGENCE / INVALID_CASH_FLOWS`.
- **Account engine.** `PerformanceService.compute(account, start, end, K)` builds start/end valuations from `ValuationService`, collects portfolio-perspective external flows, and returns `PerformanceResult(twr, modified_dietz, xirr, values, flows)`.

## 4. Three interviewer questions

**Q1. Why do TWR and XIRR disagree on the same account?**
They answer different questions. TWR removes the investor's cash-flow timing; XIRR is money-weighted and therefore rewards when the investor happened to contribute. The §7.3 gap (15.2381% vs 6.5248%) is the worked demonstration.

**Q2. When is a root "proven missing" versus merely "not found"?**
`NO_ROOT_PROVEN` requires an analytic argument (strictly negative NPV maximum); a finite grid scan can only ever yield `NO_ROOT_IN_DOMAIN`, which explicitly records the domain/grid and any nearest outside root. The scan never pretends to be a proof.

**Q3. How do you know the solver is right?**
Two ways: hand-computed fixture values from the methodology (independent by construction) and a separately written bisection solver in `reference.py` that never imports the production code. Both must agree within the E1 tolerance.

## 5. Limitations for review

- Production TWR drives end-of-day valuations at flow boundaries; overnight NAV moves enter the gap subperiods (see mapping boundary notes).
- XIRR's grid scan can miss even-multiplicity tangential roots (METHODOLOGY §7.7 limitation); the local-minimum check reduces but does not eliminate the risk.
- `NO_ROOT_PROVEN` covers the documented fixture shape; other shapes return `NO_ROOT_IN_DOMAIN`.
